# 远程协议规格

## 范围与证据级别

本文档描述 WeLearn Studio 首个里程碑所需的远程行为。它是接口规格，不是实现指南；只记录请求元数据、响应结构和可观察状态变化，不采用其他客户端的代码结构。

当前版本于 2026-08-08 根据历史客户端行为的静态清单整理。整理过程中没有使用账号凭据，也没有向服务发送请求。标记为 **未验证** 的内容，需要在公开发布前，通过仓库所有者授权的正常浏览器会话重新抓取网络请求进行确认。

观察到的服务来源：

- 应用来源：`https://welearn.sflep.com`
- 身份认证来源：`https://sso.sflep.com`
- 每个已登录账号使用一个独立且保留 Cookie 的 HTTP 会话。
- 下文中的相对路径大小写与历史观察保持一致，在实际验证确认无关前不得随意修改。

## 结果模型

每个操作都必须返回以下四种客户端结果之一：

| 结果 | 含义 |
| --- | --- |
| `accepted`（已接受） | 写入接口接受了请求，或读取接口返回了预期结构；这不能证明平台后续统计已经变化。 |
| `rejected`（已拒绝） | 服务器明确拒绝操作，或返回非 2xx HTTP 状态。 |
| `unknown`（未知） | 传输失败、超时、数据格式错误、缺少必要字段或无法识别响应，导致无法可靠判断结果。 |
| `cancelled`（已取消） | 调用方在下一步操作前或可取消等待期间请求了本地取消。 |

对于使用 JSON 结果封装的写入接口，2xx 响应中 `ret` 为数字零或字符串零时归类为 `accepted`；存在且非零的 `ret` 归类为 `rejected`。如果 2xx 响应中没有可识别结果，则归类为 `unknown`，下文单独说明的旧版心跳操作除外。传输异常属于 `unknown`，不是 `rejected`。

取消操作不能撤销服务器已经接受的请求。普通同步 HTTP 请求可能一直执行到返回或超时。客户端必须在每次请求前、工作流步骤之间以及本地计时等待期间检查取消状态。

## 公共标识与请求头

以下值共同构成远程任务上下文：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `cid` | 课程列表项目 | 课程标识。 |
| `uid` | 课程信息页面中的嵌入数据 | 学习统计和 SCO 请求使用的已登录学习者标识。 |
| `classid` | 课程信息页面中的嵌入数据 | 班级注册标识。 |
| `unitidx` | 单元在返回列表中的位置 | `scoLeaves` 使用的单元索引；当前观察为从零开始。 |
| `scoid` | 小课叶节点的 `id` | 可共享内容对象标识。 |

经过身份验证的请求依赖登录流程建立的 Cookie。课程和 SCO 操作不得切换到新的 Cookie 容器。历史请求还为课程列表、单元、小课和 SCO 操作提供了类似浏览器的 `Referer`；服务器是否强制检查该字段仍然 **未验证**。

在线预登录接口会拒绝 Requests 默认的通用用户代理，因此所有请求都使用 ASCII 应用标识 `WeLearnStudio/<version>`，同时保留接口专用请求头。

## 1. 登录

### 目的

建立经过身份验证的 WeLearn 会话，并为该账号后续所有操作保留生成的 Cookie。

### 第一步：开始授权

- 方法：`GET`
- URL：`/user/prelogin.aspx`
- 查询参数：
  - `loginret=http://welearn.sflep.com/user/loginredirect.aspx`
- 自动重定向：启用。

当前重定向链最终到达 `/idsvr/transfer.html`，其嵌套的 `returnUrl` 包含授权回调地址，以及非空的 `code_challenge` 和 `state` 查询参数。历史响应也可能直接提供该回调地址。客户端同时解析两种结构；缺少授权参数时，结果为 `unknown`。

### 第二步：提交凭据

- 来源：`https://sso.sflep.com`
- 方法：`POST`
- 路径：`/idsvr/account/login`
- 请求体编码：表单数据
- 字段：
  - `account`：用户输入的账号；
  - `pwd`：转换后的密码值；
  - `ts`：密码转换使用的十进制时间戳；
  - `rturl`：使用第一步参数组装的授权回调路径。

身份服务签发的回调地址必须原样作为 `rturl` 提交。观察到的回调包含以下授权参数：

- `client_id=welearn_web`
- `redirect_uri=https://welearn.sflep.com/signin-sflep`
- `response_type=code`
- `scope=openid profile email phone address`
- 第一步获得的 `code_challenge`
- `code_challenge_method=S256`
- 第一步获得的 `state`
- 兼容性元数据 `x-client-SKU=ID_NET472` 和 `x-client-ver=6.32.1.0`

历史密码转换属于可观察的传输要求：

1. 读取当前 Unix 毫秒时间并记为 `t0`。
2. 取 `t0` 的第 16 至 23 位作为 8 位累加器初始值。
3. 将累加器与 UTF-8 密码的每个字节依次进行异或运算。
4. 令 `r` 为累加器对 100 取模的结果，并用 `r` 替换 `t0` 十进制表示的最后两位，所得结果为 `ts`。
5. 将 UTF-8 密码编码为小写十六进制文本。
6. 对 UTF-8 文本 `<ts>*<password-hex>` 进行 Base64 编码，得到 `pwd`。

原始密码、转换后密码、时间戳、授权 URL 和会话 Cookie 都不得写入应用日志或测试夹具。

预期响应为包含 `code` 的 JSON 对象：

- `code == 0`：凭据提交被接受，继续第三步；
- `code == 1`：凭据被拒绝；
- 缺少 `code`、格式错误或尚未记录的其他值：`unknown`。

### 第三步：完成应用侧会话

在同一会话中再次执行第一步的 `GET` 并启用重定向。历史流程依赖第二步生成的身份 Cookie 完成应用回调，并设置 WeLearn Cookie。

只有凭据响应报告 `code == 0`，且最终请求以 2xx 状态完成时，登录操作才归类为 `accepted`。该最终判定比历史客户端更严格，仍需通过最新抓包 **验证**。

第一步和第二步开始前可以取消。一旦开始提交凭据，本地取消就无法保证身份会话未被创建。

## 2. 课程列表

### 目的

读取当前已登录账号可见的课程。

- 方法：`GET`
- 路径：`/ajax/authCourse.aspx`
- 查询参数：`action=gmc`
- 观察到的 `Referer`：`/2019/student/index.aspx`
- 会话：当前账号的已认证会话。

预期响应结构：

```json
{
  "clist": [
    {
      "cid": "course-id",
      "name": "课程名称",
      "per": 0
    }
  ]
}
```

`clist` 必须是列表。每个可用项目必须提供非空的 `cid` 和 `name`；`per` 是可选显示元数据，不能作为小课已完成的证明。空列表表示读取成功但没有可用课程，不属于协议拒绝。

结果分类：

- 2xx 且包含有效 `clist`：`accepted`；
- 非 2xx：`rejected`；
- JSON 无效、缺少 `clist` 或项目标识无效：`unknown`。

## 3. 课程信息初始化

### 目的

获取单元、小课、刷作业和刷时长操作所需的学习者标识与班级标识。

- 方法：`GET`
- 路径：`/student/course_info.aspx`
- 查询参数：`cid=<课程标识>`
- 会话：当前账号的已认证会话。

预期响应为包含以下应用状态的 HTML：

- `uid`：账号范围内的学习者标识，历史观察为十进制数字；
- `classid`：班级注册标识，历史观察为简单的字母、数字或下划线文本。

当前页面已观察到在普通 JavaScript 状态对象中输出这些值。客户端也接受嵌入的 `application/json` 文档。无论采用哪种形式，这一对标识都必须唯一；偶然出现的变量文本和歧义值不能被接受。

结果分类：

- 2xx 且找到两个标识：`accepted`；
- 非 2xx：`rejected`；
- 2xx 但任一标识缺失或存在歧义：`unknown`。

## 4. 单元列表

### 目的

读取一门课程中按顺序排列的单元。

- 方法：`GET`
- 路径：`/ajax/StudyStat.aspx`
- 查询参数：
  - `action=courseunits`
  - `cid=<课程标识>`
  - `uid=<学习者标识>`
- 观察到的 `Referer`：`/2019/student/course_info.aspx`
- 会话：当前账号的已认证会话。

预期响应结构：

```json
{
  "info": [
    {
      "name": "单元名称",
      "visible": "true"
    }
  ]
}
```

`info` 必须是列表。`name` 是显示名称。历史上的 `visible` 以字符串出现；在实时流量确认其契约前，该字段视为可选。返回顺序决定小课叶节点请求中的 `unitidx`，因此客户端在生成索引前不得重新排序单元。

结果分类与课程列表相同，只是使用 `info` 代替 `clist`。空 `info` 列表属于有效的空结果。

## 5. 小课叶节点

### 目的

读取一个单元下可运行的小课对象。

- 方法：`GET`
- 路径：`/ajax/StudyStat.aspx`
- 查询参数：
  - `action=scoLeaves`
  - `cid=<课程标识>`
  - `uid=<学习者标识>`
  - `unitidx=<从零开始的单元位置>`
  - `classid=<班级注册标识>`
- 观察到的 `Referer`：`/2019/student/course_info.aspx?cid=<课程标识>`
- 会话：当前账号的已认证会话。

预期响应结构：

```json
{
  "info": [
    {
      "id": "sco-id",
      "location": "单元 > 小节 > 小课",
      "isvisible": "true",
      "iscomplete": "未完成"
    }
  ]
}
```

相关字段：

- `id`：后续 SCO 请求使用的必要稳定标识；
- `location`：显示路径或小课名称；
- `isvisible`：字符串形式的可见性标记，准确拼写和所有可能值仍然 **未验证**；
- `iscomplete`：平台提供的显示状态。历史值是本地化文本，在完整值集合得到确认前，新实现不得通过子字符串解析该字段。

只有 `id` 非空且没有被明确隐藏的小课才允许选择。缺少可见性字段表示元数据未知，不等于服务器错误。

结果分类与单元列表相同。无效的小课叶节点应单独报告并跳过，不能把其状态分配给其他小课。

## 6. 作业提交

### 目的

使用用户请求的正确率，为一个已选小课提交完成度或进度更新。接口接受请求不能证明教师侧记录、分数或课程百分比已经变化。

所有步骤都使用：

- 方法：`POST`
- 路径：`/Ajax/SCO.aspx`
- 请求体编码：表单数据
- 观察到的 `Referer`：`/Student/StudyCourse.aspx?cid=<cid>&classid=<classid>&sco=<scoid>`
- 会话：读取该小课时使用的同一账号认证会话。

工作流必须按顺序执行。前置的启动请求被拒绝或结果未知时，不得继续执行后续步骤。

### 第一步：打开小课会话

字段：

- `action=startsco160928`
- `cid`
- `scoid`
- `uid`
- `classid`
- `tid=-1`

预期响应封装仍然 **未验证**。优先使用公共 `ret` 规则；在当前抓包确认该操作是否返回旧版非封装响应前，不能假定每个 2xx 响应都表示接受。

### 第二步：提交 CMI 状态

字段：

- `action=setscoinfo`
- `cid`
- `scoid`
- `uid`
- `data=<序列化状态，末尾追加字面量标记 [INTERACTIONINFO]>`
- `isend=False`

序列化状态是包含以下已观察部分的 JSON 对象：

```json
{
  "cmi": {
    "completion_status": "completed",
    "interactions": [],
    "launch_data": "",
    "progress_measure": "1",
    "score": {"scaled": "<请求的正确率>", "raw": "100"},
    "session_time": "0",
    "success_status": "unknown",
    "total_time": "0",
    "mode": "normal"
  },
  "adl": {"data": []},
  "cci": {"data": []},
  "retry_count": "0",
  "submit_time": ""
}
```

历史流量还包含其他空的 `cci` 子结构，这些结构是否必要，以及 `score.scaled` 所使用的比例都仍然 **未验证**。新客户端必须在本地验证正确率是 `0` 至 `100` 的整数，但不能声称这是服务的正式评分范围。

预期响应为标准 SCO 结果封装，使用公共 `ret` 规则分类。

### 第三步：保存摘要状态

字段：

- `action=savescoinfo160928`
- `cid`
- `scoid`
- `uid`
- `progress=100`
- `crate=<请求的正确率>`
- `status=unknown`
- `cstatus=completed`
- `trycount=0`

预期响应为标准 SCO 结果封装。第二步和第三步应分别使用公共 `ret` 规则分类。如果一个更新被接受而另一个没有被接受，小课结果应记为部分完成或未知，而不是完全接受。

每个步骤开始前都要检查取消状态。第二步完成后再取消，可能使远程状态停留在部分更新状态；目前没有已知的回滚操作。

## 7. 刷时长心跳流程

### 目的

在用户请求的本地时长内保持一个小课会话活动，并发送周期性心跳。不同课程环境对最终更新时间请求的采纳结果并不一致；当前实现恢复旧版客户端的兼容心跳行为，但仍需真实账号复测，不把单次接口接受视为最终统计保证。

所有请求都使用：

- 方法：`POST`
- 路径：`/Ajax/SCO.aspx`
- 请求体编码：表单数据
- 公共字段：`uid`、`cid`、`scoid`、`classid`、`tid=-1` 和随机 `nocache`
- 观察到的 `Referer`：`/Student/StudyCourse.aspx?cid=<cid>&classid=<classid>&sco=<scoid>`
- 会话：当前账号的已认证会话。

### 第一步：读取当前 SCO 状态，必要时初始化

先发送 `action=getscoinfo_v7`。若平台返回无法解析的未初始化状态，则发送
`action=startsco160928`，随后重新读取一次；已有有效状态时不重复启动小课会话。

附加字段：`action=getscoinfo_v7`。

预期响应为 JSON 对象，其 `comment` 字段可以是 JSON 字符串，也可以直接是对象。解码后相关结构如下：

```json
{
  "cmi": {
    "session_time": "0",
    "total_time": "0",
    "progress_measure": "0",
    "completion_status": "not_attempted",
    "score": {"scaled": ""}
  }
}
```

授权抓包中的 `session_time` 和 `total_time` 均为非负整数秒。它们是当前小课会话的计时基线，不是课程页面已经显示的历史累计值。客户端只接受能够无损解析为非负整数的值；其他格式返回 `unknown`，不得猜测或强制换算。

准确的错误封装和稳定的机器可读错误码仍然 **未验证**；新实现不得依赖本地化文本的子字符串匹配。

### 第二步：发送初始心跳并按分钟维持会话

字段：

- `action=keepsco_with_getticket_with_updatecmitime`
- `session_time=<读取到的基线 session_time>`
- `total_time=<读取到的基线 total_time>`
- 公共字段。

历史心跳返回类似票据的内容，而不是 SCO 的 `ret` 封装。在实时验证确定必要字段前，任何 2xx 响应归类为 `accepted`，非 2xx 响应归类为 `rejected`，传输失败归类为 `unknown`。返回的票据不得写入日志。

读取状态后立即发送一次初始心跳，随后使用支持取消的机制在本地等待，并在每个完整的 60 秒边界重放相同的基线状态。三分钟任务因此包含一次初始心跳和三次周期心跳，服务器可以观察到三个完整心跳间隔。不足 60 秒的剩余时间只等待，不额外发送周期心跳。遇到第一个被拒绝或未知的心跳后立即停止。

该兼容策略来自旧版客户端行为以及 2026-08-10 的真实平台对照：只在分钟边界发送递增心跳、最后调用 `updatecmitime` 时，18 个三分钟任务约增加 37 分钟；恢复初始心跳后，同样计划约增加 42 分钟，仍低于计划的 54 分钟。当前实现因此进一步恢复旧版的读取顺序和公共请求字段，并等待下一次真实复测确认，不宣称已经完整计入。

### 第三步：保存小课会话

本地计划时长全部完成后，发送 `action=savescoinfo160928`，字段包括：

- `progress`：从 `cmi.progress_measure` 读取的值，仅在请求模型中允许字段缺失时使用默认值；
- `crate`：从 `cmi.score.scaled` 读取的值；
- `status=unknown`；
- `cstatus`：从 `cmi.completion_status` 读取的值；
- `trycount=0`；
- 公共字段。

使用标准 SCO `ret` 规则分类。

只有启动、状态读取、初始心跳、每个必要的周期心跳和最终保存都符合各自接受规则时，整个工作流才归类为 `accepted`。

等待期间取消会返回 `cancelled`，并跳过尚未开始的心跳和最终保存。已经发送的心跳无法撤销。

## 请求顺序汇总

```text
预登录 -> 身份登录 -> 完成应用会话
       -> 课程列表
       -> 课程信息 -> 单元 -> 小课叶节点
                            |       |
                            |       +-> 作业 SCO 流程
                            |       +-> 刷时长心跳流程
```

每个账号拥有独立的 Cookie 容器。不同账号的任务可以并发运行，但同一个小课的请求必须保持上述顺序。

## 尚未解决的观察项

协议被视为稳定前，必须使用合成测试和仓库所有者授权的最新浏览器抓包解决以下问题：

1. 当前登录重定向链、Cookie 名称与作用域、CSRF 要求，以及 `rturl` 中兼容性字段是否仍然必要。
2. 完整的登录 `code` 值集合，以及最终预登录请求返回的响应体。
3. 完整的课程、单元和小课结构，包括标识类型、空值、可见性值、完成状态值和分页行为。
4. 课程信息 HTML 中 `uid` 和 `classid` 的结构化位置。
5. `unitidx` 是否始终从零开始，以及隐藏单元是否会影响其稳定性。
6. `startsco160928`、`setscoinfo`、`savescoinfo160928` 和心跳操作的响应封装。
7. CMI 和 CCI 字段中的必填项与可选项、`score.scaled` 的比例，以及 `[INTERACTIONINFO]` 后缀的作用。
8. 未初始化 SCO 数据、会话过期、请求限流和无权限访问对应的机器可读错误码。
